# V1.1 候选方向：用户价值与明亮暮色

状态：2026-11-16 的产品与视觉建议，尚未实施，未生成新视觉稿。V1.0 是唯一冻结基线。

## 目标

保留用户认可的原图、月夜气质和移动构图；改善中转站用户的决策效率与白天使用感受。

以下是基于产品用途的判断，不是用户访谈或转化实验结论。需通过真实流量和使用反馈校正。

## 中转站用户优先判断什么

| 用户问题 | 建议呈现方式 | 证据边界 |
| --- | --- | --- |
| 有没有我需要的模型，支持什么能力和协议？ | 首页可到达的模型检索/分类入口与简短代表模型列表 | 以实际可用模型与协议为准，避免按厂商名字推断全部支持 |
| 输入、输出、缓存分别怎样收费，最低要充多少？ | 清楚的价格入口；若展示价格摘要，明确单位、组别与适用条件 | 使用当前真实报价和已确认充值规则，不造“全网最低”或赠送额度 |
| 能否稳定调用，出现故障怎么知道？ | 服务状态与维护信息入口 | 只有在实际监控存在时显示时间范围、样本和统计口径；无证据不写可用率或延迟 |
| 能否接到我常用的客户端、SDK 或开发工具？ | 已验证工具的接入说明与必要配置步骤 | 不用兼容 OpenAI 之类泛化描述暗示所有工具和全部端点兼容 |
| 充值之后是否可控，出了问题怎么办？ | 账单可查、费用说明、支持联系方式和适用政策 | 链接真实存在的规则，不承诺未经确认的退款、售后时效或额度保障 |
| 我已有账户，怎样尽快开始？ | 清晰的进入控制台入口 | 保留正确登录态与跳转行为 |

## 推荐首页内容顺序

1. 首屏：实际插画 + 明确的模型 API 接入定位 + “查看模型与价格”与“注册并接入”两个主要入口；已有账户保留“进入控制台”。
2. 紧接首屏：选模型/看价格的入口及简短预览。若权限不允许公开价格，则保留清楚的访问条件，不绕过原有权限。
3. 接入方式：用户实际会用的客户端或 SDK，提供已经核实的短步骤。
4. 信任信息：服务状态、公告、账单透明与支持入口；无真实数据时不放数字统计卡。
5. 常见问题：协议、计费单位、如何查看用量、故障处理与支持方式。

建议首屏文案方向（待确认）：

> 银月 AI · 模型 API 中转站
>
> 把你需要的模型，接入日常工具。
>
> 查看可用模型与价格，获取 API 密钥，在客户端或应用中开始调用。
>
> 查看模型与价格 / 注册并接入

“连接模型，让灵感启程”可保留为品牌副标题。优先让用户看懂服务与下一步，不要求所有页面改成营销文案。

## 明暗改进方向

- 首页继续保留夜空插画；减轻文字区和图片上的深色遮罩，保留月亮与晚霞的明亮层次。
- 主要内容区使用带蓝紫倾向的月白/晨雾色，让首屏之后有视觉休息，不连续堆叠深色卡片。
- 控制台先比较“暮色”方案：整体介于深夜与纯白之间，保留云霞图像，降低大面积深蓝的占比，内容面板有明显明度区分。
- 现有 V1.0 深色保持为对照，候选浅色/暮色单独出稿；是否成为默认模式需确认，不立即替换用户已有偏好。
- 深浅主题都要来自相同的图像与品牌配色。提高亮度不等于退回用户已否定的纯色通用后台。
- 数据区阅读对比与装饰区域分开控制；不要只降低面板透明度来提亮，否则图片会干扰文字。

## 开发与版本安排

- 本轮只冻结 V1.0 并记录建议。
- V1.1 先生成独立的首页与控制台桌面/手机对照稿，记录改动目的。
- 比较时保持相同的数据、内容量和设备宽度，避免因为内容减少而误判布局更好。
- 用户选择后再进入正式 React 改造；继续执行 V1.0/DESIGN.md 的复用、移动验收与业务隔离要求。
- 衡量改善可观察：模型价格入口点击、接入文档到达、注册到首次成功调用、手机端主要操作完成情况；此处只提出指标，不声称已部署统计或得到转化数据。
