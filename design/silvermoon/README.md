## 如何查看与找回

- 完整目录必须一并保存：`index.html`、`assets/`、`screenshots/`、`source.html`、`DESIGN.md`、`manifest.json`、`SHA256SUMS`。
- `index.html` 是资源本地化的预览入口，可直接打开；使用 HTTP 预览时，从此目录启动仅监听本机的静态服务。运行目录应为归档本身，不需要旧运维目录、数据库或生产账户。
- `source.html` 是冻结时当前预览的逐字节副本，保留当时外链；离线预览使用 `index.html`。
- `screenshots/` 保存当时的桌面首页、桌面控制台、手机首页、手机控制台及手机并排稿，作为视觉对照。
- 在 `versions/v1.0/` 内运行 `sha256sum -c SHA256SUMS`，检查归档是否被改动。
- 本地 Git 标记为 `design/silvermoon-v1.0`。在仓库内执行 `git archive --format=tar --output=/tmp/silvermoon-design-v1.0.tar design/silvermoon-v1.0 design/silvermoon/versions/v1.0`，可导出该版，不覆盖当前开发文件。
- 本次为本地归档与本地 Git 版本标记，尚未推送远端。不能将其描述为已完成异地备份。

## 后续版本规则

1. 冻结版本不覆盖。新的布局、配色或文案从独立版本目录开始，例如 `versions/v1.1/`。
2. 每版记录：用户目标、与前版的区别、视觉规范、桌面和手机截图、实施入口、交互约束、验证结果、未实现事项。
3. 将“建议”“设计稿”“用户确认”“已开发”“已部署”分别记录，不以截图或设计稿代替实际开发状态。
4. 保留原始来源副本和本地资源，生成校验清单；图片与字体不得只依赖外链。
5. Git 标记使用 `design/silvermoon-vX.Y`。不要使用发布流水线的 `v*` 标签，不因设计归档发布镜像或部署服务。
6. 后续选择其他方案不会删除 V1.0。若新稿不理想，直接以 V1.0 作为对照或恢复起点。

## 已明确的用户偏好

- 不喜欢数据卡顶部彩色细线、侧栏选中项装饰竖线带来的模板化与 AI 生成感；后续优先以底色、文字和间距区分层级，保留必要的键盘焦点提示。
- 银月品牌，轻动漫、月亮、人物、云霞、倒影与电影感天空；图片是核心视觉资源。
- 已否定仅靠纯色与简化月亮组成的初始草稿，不再把它当作设计基础。
- 大量用户使用手机；手机首页、控制台、菜单、表单和列表是主要验收对象。
- 2026-11-16 用户明确要求页面不出现 “Powered by New API …” 展示；V1.0 保存的是该要求之后的独立设计稿。本次未修改产品源码中的版权、许可证或署名。
- 当前版本的暗色强度和中转站用户转化内容仍待讨论，记录于 NEXT.md；不要将下一版建议混入冻结稿。
