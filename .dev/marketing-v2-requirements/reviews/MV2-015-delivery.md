## 当前交付对象

从正式 `custom/main` 基线 `ca5af4c3fb5a9fdae8eb0a780f86ee1546230f12` 开发的新营销 v2。旧营销 v1 从未上线，不迁移或导入旧预览数据。现有正式 New API 的用户、余额、支付、兑换码、日志与未结任务必须保留并核对。

部署约束：全部 New API 实例共享同一 PostgreSQL 业务库及同一 Redis 服务、同一逻辑库；复用现有数据库任务调度，无新增消息队列。后台恢复至少有一个 master 运行，多 master 通过现有数据库租约调度，资金效果仍由业务事务和唯一事实约束保证。Redis 缓存不能作为余额、机会、库存或首充资格的最终依据。

交付前置：机器验证、全部原 A01–A06 独立复核及用户人工验收结果齐备；本地 commit 仅保全代码。推送、PR、发布镜像及线上切换分别按用户授权执行。本任务不自动执行这些动作。

## 正式切换步骤

1. **盘点版本与依赖。** 保存当前镜像 digest、运行配置、实际实例清单、PG 版本及 Redis 逻辑库。把主实例、从实例、定时任务、长连接、异步任务及进程内待写队列都纳入清单。
2. **完成可恢复备份。** 对业务库和独立日志库（如果使用）分别备份；安全保存会话／加密配置及运维配置，不将密钥放进 Git、证据 JSON 或操作日志。先在隔离副本执行恢复与来源盘点，确认可恢复后才继续。
3. **停接新写入并排空。** 同时停止新模型调用、充值／兑换、活动参与和管理员资产修改。保留已接受支付的回调处理与记录，直至受理中的支付得到明确处置；如回调暂不可接收，记录未处理订单并在新版恢复后按同一订单重试。停止新写入不能等同于取消已成立的支付或费用。
4. **核对长连接及异步任务。** 等待在途正常结算；断开的 Realtime、流式或异步任务如费用未知，须按供应商可信终态及原来源核对。不能因为进程停止就归零费用、释放全部资金或允许退款。无法核实的账户继续阻止新消费／清退，保留待核对依据。
5. **停止所有旧写入者。** 确认旧版本实例、批量队列与后台任务不可能继续写同一业务库，再迁移。不能一边滚动运行旧余额写法，一边启用新来源账本。
6. **迁移并核实历史来源。** 在统一新版启动过程中运行已验证的迁移，核对新增表及恢复索引。按 [维护操作手册](../validation/maintenance-runbook.md) 先预览历史余额、邀请余额、支付／兑换和未结任务，再根据真实来源执行核实。不能把旧混合余额、旧赠送或管理员调整一律记作付费金额；零余额也不能推断从未充值。
7. **统一配置后恢复流量。** 全部实例使用同一新版镜像与共享库／缓存，至少一个 master 开启现有任务调度。核对人民币易支付、付费兑换码信息及站点金额换算；不启用 Stripe、订阅或旧营销赠送入口。先用受控账号验证新入账、签到、抽奖、混合资金消费和原路返还，再恢复正常流量。
8. **观察并保留证据。** 检查系统任务失败、待发活动奖励／已开奖未发奖、费用待核对、数据库锁等待与错误率。进程重启后后台会继续处理持久义务；活动结束不抹掉先前已成立的奖励，抽奖恢复不重新选择奖项。

## 回滚边界

- 新版尚未产生任何新业务写入时，可在全实例停写后依据已验证备份恢复对应旧版本数据库与配置，再启动原镜像。结构回退不能仅靠切换二进制。
- 一旦新版已产生支付、赠金、消费、机会或现金退款登记，**不能把旧数据库备份直接覆盖回去**；这会丢失真实业务事实。先停接写入、保全当前数据库和日志，再在隔离副本核对增量及拟定回退方案。优先修复后继续运行新版。
- 不能让原版本直接写新版来源账本，也不能将赠金合并回付费金额。撤销未完成发布与撤销已发生收款／消费是不同操作。

## 已知限制与运行建议

- 现金退款仍由管理员在支付平台执行；系统维护入口登记可核实现金、清退剩余付费金额／赠金／机会／累计余数并保留追溯。先禁用用户，处理完在途和未知费用再清退。重新启用不会恢复旧权益。
- 奖励正常同步发放；瞬时错误和进程退出后的补发由后台恢复。永久性数据问题、禁用受益人或需核对的资金问题不会被后台伪装为到账，系统任务保留错误，需管理员定位。没有人工审核领取流程。
- 抽奖供给不足不会自动改概率、拆发机会或追补历史名额不足资格；追加只服务之后成立的新资格。技术失败的已承诺奖励则恢复原义务。
- 性能数据仅适用于本次共享测试宿主机、本地模拟上游和明确资源限制。单账号热点受资金行锁串行化影响，不能用分散用户吞吐承诺单账号能力。生产应按真实上游时延与部署资源调整数据库连接池；不要盲目把各实例连接数相加到超过数据库容量。
- 原始未知费用和真实资源不足继续保留待核对；未上锁的缓存余额不能授权超额消费。日志默认每次调用一条逻辑记录，赠金／付费金额只在同条记录内拆分。
