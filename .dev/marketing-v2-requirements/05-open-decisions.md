## 已关闭，不重新询问

- **Realtime 供应商范围（2026-11-23）：** 用户确认没有指定供应商限制，不能要求用户提供一个限定供应商名单才能继续开发。沿用项目支持的协议和通用扣费边界，不新增营销供应商白名单。协议差异由开发核对，未验证的供应商能力不能宣称已验证。

- **N05 已关闭（2026-11-22）：** 用户确认退款完成后清零剩余付费金额、限时／永久赠金、未使用机会与累计充值未满档余数；保留历史账目、已领取次数、首充资格等领取事实。清零前完成在途结算，重新启用账号不恢复旧资产与机会。具体清零留痕须开发实现，现有普通禁用不自动承担清零职责。

- 四类活动、充值三类五玩法；累计首次一次按每用户每活动。
- 充值/签到/邀请/抽奖所有充值门槛按实付人民币。
- 兑换码只用于正式付费充值，不支持赠送码；记录实付，并与在线支付统一入账及活动资格判断。
- 两种累计比例赠金都明确不支持，不再列待定。
- 赠金取消指定模型与调用分组限制，调用范围与付费金额一致；不取消原账户权限、赠金有效期和资产隔离。
- 使用记录一次调用一条，列表总费旁显示赠金部分、详情显示两类承担，不拆成两条调用记录。
- 退款后按用户要求复用账号禁用，不新建“退款并停用”的专门流程；禁用范围与已建立连接行为需真实核验。
- 签到三种条件，补签每活动每用户总上限、跨月不重置。
- 所有营销奖励正常即时自动发放，赠金到账生效；不支持人工审核、手动激活或激活截止。每日与连续奖同活动叠加。
- 钱包首页只展示剩余付费金额和剩余赠金，点击赠金看来源、消费、剩余及有效期；预扣占用属于内部机制，不铺开为用户钱包状态。
- 邀请按好友分别累计，一次/循环均支持；比例基于好友实付，老邀请排除。
- 机会方式与开奖结果分开配置，直接／概率发机会均可对应必得赠金或允许未中奖的奖池；按权重抽取，不按库存份数抽取，非消费触发，不展示累计进度。
- 不增加积分、主题奖品、订阅、自动 VIP 返还或外部中间件。

## 旧规则不再作为新开发依据

| 旧材料中的内容 | 新规则 |
| --- | --- |
| 按自然月补签上限 | 整个签到活动每人上限 |
| 活动引用另一个抽奖活动、暴露内部 ID | 独立奖池，按名称选奖池 |
| 固定概率区间加必选替代奖，某区间不可发则停全池 | 可用奖项按配置权重抽取，单奖耗尽不停止其他奖项 |
| 活动选择A/B/C并限制兼容奖池 | 活动仅管机会，奖池决定是否未中奖；两种机会方式与两类奖池均可组合 |
| 模型消费达标给本次充值抽奖资格 | 按活动内实付充值累计 |
| 单笔余数不跨单的旧抽奖玩法 | 本次明确的循环累计跨订单留余数 |
| 累计条件可任意搭配比例赠金 | 首次/循环累计比例均不支持 |
| 兑换码选择付费或赠送、赠送码生成赠金 | 兑换码统一用于付费充值，赠金由营销活动另发 |
| 手动激活、激活截止、人工审核及拒绝发奖规则 | 所有奖励自动发放，赠金即时生效；故障内部恢复，不新增用户操作 |
| 钱包首页按资产和各类金额状态拆分多个卡片 | 剩余付费金额＋剩余赠金，来源/消费/有效期放明细 |
| 赠金按指定模型/调用分组限制可用范围 | 取消赠金专属范围限制，沿用付费金额的调用权限 |
| 建设退款处理状态机和逐项冻结/清退流程 | 人工退款，使用已有账号禁用操作阻止继续调用；退款完成后按已确认范围清零并留痕，但普通禁用本身不清零 |
| 旧分支实现可直接迁入新分支 | 仅参考，基于干净主分支重新设计实现 |

旧已完成验收及其锁定文本保留历史，不改为未完成、不改字后宣称新版通过。新的 Issue 要有独立验收基线。

### N01 已确认部分与剩余问题（2026-11-22）

用户明确确认“活动达标后自动获得机会，奖池总份数约束可发机会，用户再主动抽奖”；没有手动领取机会的新环节。已发但未使用的机会也需要可兑现的奖品供给，组合奖按一份奖项计算。详见03。

已确认公开限量规则及剩余名额，抽奖作为附加福利，不设支付预留，管理员按实际供给主动追加并留痕。未发机会名额和用户已拥有机会分开。

以上剩余边界已在开发阶段全部确认，见顶部N01–N04/N06与下节；资源耗尽不能一律未中奖。

## 2026-11-22 开发阶段最新确认

上述N01–N04/N06已由用户逐项答复关闭，覆盖本文件及03、原型历史中“尚待确认”的旧描述。名额不足是已处理资格的明确未发原因，不是概率未中，也不是已承诺但技术失败的待发任务；后者仍按原事实恢复，不受“追加不补历史资格”影响。
