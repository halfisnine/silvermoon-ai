## 2. 管理员：营销活动列表和共同字段

列表建议显示：活动名称、类型、活动时间、运行状态、奖励摘要；操作为新建、查看、编辑、启用/暂停。运行状态表达活动是否开放，不是资金状态。已发奖励保留当时依据；开始后核心规则不可原地改，用复制新对象调整；补库存/追加和延期遵守05，已有供给责任和旧截止不能受损。

2026-11-25 用户确认后台列表整理：活动和奖池支持归档、恢复，列表默认“未归档”，可切换“已归档／全部”。归档仅改变管理员列表归类，不改变启用、暂停、发布、时间、互斥资格或任何用户侧可见性与权益；用户仍可参与符合原规则的活动、使用有效机会、查询奖励和赠金。后台奖励筛选、奖池关联选择与互斥组成员查询仍包含归档对象。仅从未启用且无关联业务记录的活动草稿允许删除；奖池仅在尚未开始、未发过机会、无关联业务记录且未被任何活动普通／连续签到奖励引用时允许删除。服务端在事务内复核，操作凭据保留；其余对象通过归档整理，不删除历史。

点击新建先选四张场景卡：注册有礼、签到奖励、充值奖励、邀请奖励。共同填写活动名称、时间、场景条件和奖励，最后核对自动生成的规则摘要再发布。

活动时间支持已确认的长期或指定起止时间；签到优先呈现起止日期，按用户短期活动场景配置，不擅自删除其他场景的长期能力。既有叠加/互斥及优先级放在可折叠高级设置，不向用户转交活动选择。

高级设置不作为旧配置的兜底入口：人工审核、激活、模型/分组限制仍禁止；首期不设活动赠金预算或通用奖励次数限制；奖池发行总名额必须有限，不能把三套旧限制塞进去。

P1.1 明确互斥含义：对同次行为中确实符合条件的活动，允许叠加的活动独立发奖；只有属于同一个互斥组的活动才比较优先级。例如 A 允许叠加，B/C 同组且 B 优先级较高，结果为 A＋B；B/C 不同组且各自没有其他更高优先级的合格活动，则 A/B/C 均可生效。同优先级保持既定确定顺序；首期无赠金预算分支；高优先级活动机会名额不足不改选低优先级，独立赠金照常。

互斥组交互调整建议：选择已有组，显示组内已有活动和优先级；需要时在当前页新建并选择，不依赖反复手填相同名字来关联。名称是可读标签，关联指向同一个组，改名不应改变已有成员关系。原型只在内存演示选组，不表示已经实现后台组管理。

## 3. 共用奖励编辑区

直接在活动里添加奖励行，不要求先建立模板。可选预设不成为必经步骤。

| 奖励类型 | 显示字段 | 显示条件/依据 |
| --- | --- | --- |
| 固定赠金 | 金额；限时/永久；限时的有效时长 | 注册、签到、充值达标、邀请注册/累计达标 |
| 充值比例赠金 | 比例；限时/永久；限时的有效时长 | 仅基于单笔事实的充值奖励，明确基数为该笔到账付费金额 |
| 邀请比例赠金 | 比例；限时/永久；限时的有效时长 | 邀请比例场景，明确基数为好友该笔实付人民币 |
| 抽奖机会 | 按名称选择奖池；次数 | 对应活动允许的机会奖励 |

固定金额和赠金按站点金额配置显示并安全换算，充值门槛和实付售价明确为人民币。时长使用易懂的时分/天选择，不要求管理员填写内部秒数。永久不显示时长。

用户已明确：上述金额规则同时约束管理员和用户。赠金金额、奖品金额、兑换到账金额等直接输入和回显站点设置换算后的金额，并标明货币单位；不让管理员填 500000 等内部 quota 再看旁注换算。该要求覆盖本稿所有相关表单、列表、详情、摘要及错误提示。充值门槛和实付售价仍明确使用人民币，不能与账户展示金额混淆；具体约束见 04 的“金额输入与展示”。

同一奖励可以多行组合，例如“限时赠金 2 元＋永久赠金 1 元＋抽奖机会 1 次”。不出现“模板面额虽然无用仍必须填”或层叠份数乘数。

P1.1 按用户反馈采用平铺行式布局：一项奖励一行，直接排列内容、金额/比例、赠金类型、有效时长及移除操作；组合奖励追加行。连续签到每个档位用标题和分隔线区分，内部奖励不再包一层卡片。奖池每个奖项同样平铺奖项名称、权重、库存及其赠金行，使用分隔线区分奖项；手机端按字段换行，不通过多层边框与缩进表达层级。字段和业务能力不因压平布局而减少。

累计条件选中后不提供比例赠金，后台提交也禁止；不以灰色高级开关保留。没有激活方式、激活截止、审核方式、模型白名单或调用分组字段。

## 4. 注册有礼表单

只有：活动名称、活动时间、奖励编辑区，以及按需的活动叠加设置。

固定说明：“注册成功后自动发放，赠金到账即可使用。”不让管理员填“注册成功”条件表达式，也不再填一个通用次数上限来保证同次注册只发一次。

流程：管理员配置发布 → 新用户成功注册 → 系统按活动资格自动发奖 → 钱包/机会更新，记录来源。

## 5. 签到奖励表单与用户流程

| 区域 | 字段与交互 |
| --- | --- |
| 参与条件 | 不要求充值／当天累计实付达标／前一天累计实付达标；后两者填写人民币门槛 |
| 每日奖励 | 共用奖励编辑区 |
| 连续额外奖励 | 开启后显示“一次性／循环”、循环天数（仅循环）、第几天及额外奖励档位 |
| 补签 | 开启后显示“允许补最近几天”“本活动内每人最多补几次”“是否补发当日每日奖励” |

不开启连续或补签时隐藏其无关字段。一次性连续档位无需填周期；循环档位天数不能超过周期。规则摘要明确连续奖是额外赠送、补签次数整个活动共用且跨月不重置。

示例摘要：“每日签到送 1 元，连续 7 天额外送 2 元；每人本活动可补签 2 次。”无其他阻断条件时，第七天自动得 3 元，不增加领取按钮。

用户使用“活动 → 签到”独立页面，个人资料仅保留跳转快捷入口。卡片展示每日奖励、今日是否已签到、连续天数、下一个连续奖励、可补日期和相应活动剩余补签次数；未开启连续奖励或补签时隐藏相应内容。多活动的补签次数不能合并成一个虚假公共次数。正常签到由服务端判断所有适用活动；补签选择历史日期，检查目标日资格。界面不让用户选择一个低优先级活动来绕过互斥或领取次数。

管理员在营销管理中配置签到活动，原卡片接入活动规则并统一发奖，原签到奖励不能与新活动并行重复发放。卡片负责签到情况与规则展示；到账赠金在钱包的赠金明细中标注签到来源、消费和剩余金额，无需另点领取。

## 6. 充值奖励表单

| 条件选择 | 后续字段 |
| --- | --- |
| 全站首笔充值达标 | 实付门槛；说明“只有本站第一笔成功充值满足门槛才奖励” |
| 活动内单笔达标 | 实付门槛；首次单笔达标一次／每笔达标 |
| 活动内累计达标 | 实付门槛；首次累计达标一次／每累计满额 |

下面接奖励编辑区。累计只从本活动开始，每人独立判断；不再显示消费门槛、月累计或旧的大档余数换小档的配置。

选择充值累计送机会时，活动只配置“机会发放方式”：达标直接赠送／达标按概率赠送；后者增加获得机会概率。机会次数、目标奖池按名称配置。所选奖池独立决定是否允许未中奖，活动不限制或自动替换为另一类奖池；摘要分别保留机会方式和所选奖池信息。

本次取消A/B/C组合限制，允许概率获得机会后仍可能未中奖。概率发放的场景范围维持原充值累计条件，一般注册／签到不自动增加概率表单；组合中的固定赠金不随机会概率变成概率发放。

流程：在线充值或付费码兑换入账 → 判断条件/频率 → 固定赠金自动发放、机会按配置授予 → 用户主动使用机会抽奖。不开用户累计进度条，不显示“还差多少充值”。

## 7. 邀请奖励表单

2026-11-25 用户侧最新确认：邀请有礼左侧活动区只展示进行中的邀请活动，不显示未开始、暂停或已结束活动；此范围仅用于该页面左侧，不改变活动中心展示范围。右侧好友、实际奖励汇总、历史奖励查询及分页保持原样，不受左侧活动筛选影响。

| 条件选择 | 后续字段 |
| --- | --- |
| 好友注册成功 | 固定奖励编辑区 |
| 好友累计充值达标 | 每位好友的实付门槛；每位好友首次一次／每累计满额；固定奖励编辑区 |
| 好友充值比例奖励 | 比例与赠金有效期，基数说明为好友实付人民币 |

固定说明：“仅本活动期间建立的邀请关系参与；充值须在活动期间成功入账。”不添加“老好友也参加”开关，不默认永久返奖。

用户在“活动 → 邀请有礼”分享；好友行为达标后邀请人自动得奖。A 好友和 B 好友分别计算，不能拼成一档；本人注册礼与邀请人奖励各归其主。比例奖励不擅自附带未定义的比例换算抽奖次数。

## 8. 抽奖管理表单

P1.2 参考用户提供的页面组织方式：基础信息 → 概率概览 → 可收起的奖项列表 → 可展开的库存耗尽演算 → 固定操作栏。每个奖项的摘要显示名称、奖励内容、当前计算概率和配置总份数/不限数量；展开后仍以紧凑行式编辑赠金，不逐层嵌套奖励卡片。支持复制和上移/下移，排序只改变展示顺序。

概率概览随输入变化，包含允许未中奖时的空奖权重；明确当前计算假设库存充足，库存演算是另一组条件下的结果，不承诺长期固定概率。所有赠金奖项耗尽后只剩空奖的数学结果，不代表批准继续消耗用户机会，实际供给与已承诺机会必须满足05约束，不能通过空奖兜底超发。用户内容预览不显示后台概率。

固定操作栏只提供保存演示草稿和核对摘要；不把参考稿的立即发布、累计保底、现金/实物/积分等奖品、10 个奖项上限、中奖跑马灯或额外风控模块带入。演示草稿与复制操作只影响当前浏览内存，不构成正式业务的版本发布方案。

基础字段：奖池名称、抽奖开放时间、是否允许未中奖；每个真实奖项填写奖项名称、赠金内容、权重、库存限制及数量。一次奖项可组合多份赠金。组合入口明确命名为“添加组合奖品”，说明“抽中此奖项时，以下赠金将一起发放”；每份赠金不单独参与抽奖，默认只显示一份，需要组合时再添加。权重为后台设置，转盘和盲盒共用算法；不强制前台显示具体概率。

允许未中奖时设置“谢谢惠顾”的权重，不把空奖当作零元赠金库存。单奖库存耗尽退出实际抽取集合，不采用必选替代奖。

正式表单按05已确认规则：发行总名额有限，允许补原库存和追加；核心规则复制新对象，旧机会截止不提前，仅延期有效机会。原型历史版本不作为完整发布实现。

用户入口显示奖池、已有可用次数、对应截止信息、奖品与抽奖按钮。使用一次机会开奖：中奖则自动发放赠金；所选奖池允许的正常未中奖则消耗机会并记录结果，不显示到账、不产生零元赠金。截止展示按05已确认的N03，不直接套来源活动结束时间。中大奖耗尽后的展示诉求保持 03 中的记录，本稿不重新决定。

## 9. 管理员奖励记录

列表建议：时间、用户、来源活动、触发原因、奖励内容、自动发放结果；详情关联充值/卡密、签到日期、好友或抽奖结果。普通运营看可读名称，不先暴露内部事件编号。

可以按用户、活动、时间查询。正常到账显示已发放；技术失败显示真实异常供排查，保留内部恢复而不重新开奖，不提供“审核通过/拒绝”流程。未获批准的手动补发按钮及其权限、资金操作不在本稿自行加入。

## 10. 兑换码与退款操作

保留主分支的兑换码管理与用户兑换入口。名称、数量、码有效期沿用现有用途；新版补齐实际支付人民币、到账付费金额的明确记录和必要销售来源。具体金额输入联动以主分支核对后的表单方案为准，不将两者混成一个无法追溯的字段；正常等额销售避免重复录入，不能假定折价也等额。

销售渠道/批次/凭据用于来源核对，不搬旧后台字段或擅自全设必填。没有兑换码资产类型选择，不配置赠金；兑换触发充值活动产生的赠金由活动独立发。

退款不新增页面、按钮或流程。用户联系管理员，人工处理，复用用户管理的禁用账号功能；禁用不代表退款已记账、余额已清空或已有长连接瞬间停止。N05 已确认退款完成后的清零范围，见 04：付费金额、赠金、未用机会与累计余数清零，历史和已领资格保留。此为待开发能力，不是现有禁用自动完成；不新增自动解冻功能。

## 11. 钱包、赠金明细与使用日志

钱包首页仅两项：

```text
剩余付费金额   ¥100.00
剩余赠金       ¥15.00    查看明细
```
