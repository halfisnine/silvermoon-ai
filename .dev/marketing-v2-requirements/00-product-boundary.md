## 已确认做什么

| 范围 | 用户看到或管理员操作的内容 |
| --- | --- |
| 注册 | 简单注册有礼，成功后即时自动发奖 |
| 签到 | 完整签到界面移至“活动 → 签到”，个人资料保留跳转快捷入口，由营销活动统一发奖，不与原签到奖励重复发放；每日奖与连续额外奖同活动叠加；三种参与条件；补签上限每人每活动总量，跨月不重置 |
| 充值 | 首笔达标、单笔达标、累计达标三类条件；对应一次/每笔/每满额五种玩法；门槛只计实付人民币 |
| 邀请 | 好友注册、好友累计一次/循环、好友实付比例奖励；好友分别统计，活动前老邀请排除 |
| 抽奖 | 独立奖池；活动发机会、奖池定开奖结果，支持两种发放方式与两种结果配置独立组合；按可用奖项配置权重抽取；赠机会与用户主动抽奖分开 |
| 兑换码 | 仅用于正式付费充值；记录实付并统一参与充值资格判断 |
| 奖品 | 限时赠金、永久赠金、指定奖池机会及已支持的组合；正常即时自动发放 |
| 钱包 | 首页只显示剩余付费金额与剩余赠金；赠金明细看来源、获得、消费、剩余、有效期 |
| 金额交互 | 用户和管理员均输入、查看站点货币设置换算后的金额，不暴露原始 quota；实际支付人民币字段单独明确单位 |
| 使用日志 | 复用现有页面；消费行显示总费及赠金部分，详情再拆付费与赠金；不因资金来源拆两条消费日志 |
| 退款后的操作 | 人工退款并复用账号禁用；退款完成后清零付费金额、赠金、未用机会及累计余数，保留历史与已领资格；不建设退款工单 |

详细条件和例子见 02；资金口径见 04。普通逐笔比例赠金和邀请比例奖励保留各自已确认基数，不能因同叫“比例”就混用。

## 明确不带入新版

- 人工审核发奖、审核队列、审核拒绝及超时审批规则。
- 手动领取/激活赠金、待激活状态、激活截止时间。
- 赠金指定模型或调用分组限制。
- 免费赠送兑换码、付费/赠送码分类选项。
- 首次累计或循环累计达标后的比例赠金。
- 退款工单、专门退款状态机、一键退款清零、逐份赠金冻结/解冻管理。
- 钱包首页的占用/待审/待激活状态卡片，或拆成多个用户钱包。
- 金额表单、列表、详情和提示向用户或管理员暴露原始 quota，或要求填写内部整数再通过旁注理解金额。
- 重复建设消费记录页，或把一笔消费按来源拆成两条调用记录。
- 按自然月重置补签次数。
- 固定概率加必选替代奖的旧奖池设计、按剩余份数抽取的第二算法。
- 用模型消费代替本次充值抽奖条件、累计进度促充提示。
- 积分、主题奖品、订阅、自动 VIP 等级/月返以及新中间件。

## 不自动决定

奖池预算/机会供给不足、库存与概率修改/轮次、机会截止与暂停、活动修改后的余数等，见 05。建议不是批准需求；未决部分不得用旧实现填空，也不作为必须启用旧系统的理由。

## 底层保障的边界

付费与赠金独立记录、来源关联、防重复、并发扣费/预扣结算、到期处理和技术故障恢复，是已确认行为正确运行所需的内部保障。不能借这些保障增加用户审核、激活步骤或额外管理员表单。主分支通用组件与基础设施可以按仓库规则正常使用；旧营销实现仅在明确问题需要参考时查看，不复制、合并或搬迁提交。
